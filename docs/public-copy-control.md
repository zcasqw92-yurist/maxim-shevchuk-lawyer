# Контроль публичного текста статей

Правило действует для каждой новой и изменённой статьи.

## До публикации

1. Запустить `npm run test:public-copy`.
2. Проверить текст новой или изменённой статьи.
3. Одновременно повторно проверить исходные данные всех ранее опубликованных статей.
4. Заблокировать публикацию при обнаружении:
   - внутренней SEO- или редакционной терминологии;
   - пояснений о происхождении материала, оплаченной практике или внутренних исследованиях;
   - служебных идентификаторов источников;
   - черновых инструкций, TODO, шаблонных и системных артефактов.

## После публикации

После подтверждения production SHA workflow запускает:

```bash
node scripts/live-public-copy-regression-test.mjs
```

Проверка открывает на основном домене все опубликованные статьи, анализирует видимый текст внутри `<main>` и сохраняет результат в `reports/public-copy-regression.json`.

Публикационная сессия не завершается, пока эта проверка не пройдена.

## Отчёт пользователю

В итоговом сообщении по публикации обязательно указывается один из двух вариантов:

- «Контроль прежних статей пройден, замечаний не найдено»;
- перечень каждого найденного URL, проблемной фразы или блока, выполненного исправления и результата повторной проверки.

Находка в ранее опубликованной статье сообщается пользователю так же явно, как находка в новой статье. Скрывать исправление только потому, что проблема обнаружена во время контрольной регрессии, запрещено.

GitHub Actions не может самостоятельно начать новый диалог в ChatGPT. Поэтому сообщение передаётся в том же чате, в котором выполняется и контролируется публикация, сразу после получения результата post-deploy проверки.
