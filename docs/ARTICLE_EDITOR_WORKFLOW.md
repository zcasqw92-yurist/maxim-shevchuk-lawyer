# Редакторский шлюз статьи перед публикацией

Этот протокол обязателен для каждой новой или изменяемой статьи `yuristshevchuk.com` и действует до общего `29_Публикационный_шлюз`.

## Единственный редактируемый источник

Живая Google-таблица `Юридическая воронка — БПЮ и Юр. доки`, вкладка `34_Редактор_статей_сайта` (gid `340000340`) — единственный источник публичного текста статьи между подготовкой и публикацией.

Бот сначала полностью собирает там страницу в реальном порядке отображения: метаданные, H1, lead/short answer, H2/H3, абзацы, списки, risk/note, CTA, FAQ, related и author. Пользователь редактирует текст и действия непосредственно в этой вкладке. Текст из чата, памяти бота, локального черновика или старой выгрузки не имеет приоритета над живым редактором.

## Что считается разрешением на публикацию

Разрешение появляется только после двух событий в правильном порядке:

1. пользователь проверил актуальные строки статьи в `34_Редактор_статей_сайта`;
2. пользователь затем дал в чате явную команду начинать публикацию этой версии.

Статус `ОДОБРЕНО ПОЛЬЗОВАТЕЛЕМ` в таблице сам по себе не является командой. Старое согласие не переносится на изменённую версию.

## Обязательный финальный preflight

После команды пользователя и **до любого изменения production-source** бот заново читает все строки актуальной статьи из редактора. Нельзя использовать ранее прочитанный snapshot.

Проверяются как минимум:

- опечатки, орфография, пунктуация и явные грамматические ошибки;
- естественность формулировок и отсутствие случайных повторов;
- последовательность и полнота H1/H2/H3;
- отсутствие дублирующихся или потерянных абзацев/пунктов;
- соответствие CTA и FAQ содержанию статьи;
- ссылки и действия;
- внутренние ID, SEO-термины, редакторские комментарии и черновые артефакты в публичном тексте;
- согласованность slug, title, description и первого экрана;
- сохранность структуры и порядка блоков.

Если найдена хотя бы одна проблема, публикация немедленно останавливается. Бот перечисляет находки пользователю в чате. Молча исправлять их и продолжать публикацию запрещено. Сначала пользователь согласует исправление и дальнейшее действие; после правок бот снова читает живую вкладку и повторяет preflight.

## Snapshot и fingerprint

Только после чистого и согласованного preflight бот:

1. нормализует текущие строки по `config/article-editor-gate.json`;
2. создаёт SHA-256 fingerprint;
3. записывает snapshot/fingerprint в скрытую вкладку `_35_Версии_статей_сайта` (gid `350000350`);
4. создаёт approval manifest в `reports/article-approvals/`;
5. фиксирует fingerprint и доказательство явной команды в технических колонках редактора.

Fingerprint строится по `Article_ID`, версии, slug/URL, порядку, типу блока, тексту/значению и ссылке/действию. Пользовательский комментарий и технические статусы в fingerprint не входят.

## Защита от дрейфа

Перед созданием/изменением production-source и ещё раз непосредственно перед merge бот заново читает живую вкладку и пересчитывает fingerprint.

Если fingerprint отличается от одобренного:

- разрешение считается аннулированным;
- PUB-029 не может стать `ПРОЙДЕНО`;
- production-source не публикуется;
- нужен новый финальный preflight и новая явная команда пользователя.

Запрещено перезаписывать старый approved snapshot новым содержимым так, будто изменений не было.

## Связь с общим publication gate

Для типа изменения `Статья` обязательны пять дополнительных блокеров в `29_Публикационный_шлюз`:

- `PUB-025` — статья берётся только из редактора;
- `PUB-026` — есть явная команда пользователя;
- `PUB-027` — финальный preflight выполнен после этой команды;
- `PUB-028` — зафиксированы snapshot и SHA-256 fingerprint;
- `PUB-029` — перед source-change/merge нет дрейфа относительно одобренной версии.

Пока любой из них не подтверждён доказательством, `B2` обязан оставаться `MERGE ЗАПРЕЩЕН`. После merge продолжает действовать обычный post-deploy контур до `L2 = ПУБЛИКАЦИЯ ЗАВЕРШЕНА`.

## Нормальный рабочий цикл

`исследование → полностью структурированная статья в 34_Редактор_статей_сайта → пользовательская редактура → явная команда «публикуй» → повторное чтение редактора → финальный preflight → если есть замечания: остановка и согласование → повторный preflight → snapshot + fingerprint → production-source только из snapshot → полный PR CI → повторная проверка fingerprint → merge → exact production SHA → HTTP/public-copy → IndexNow`.
