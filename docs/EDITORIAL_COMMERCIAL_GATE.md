# Коммерческий редакционный шлюз статей

Шлюз дополняет действующий алгоритм подготовки статей и не меняет SEO-preflight, владельца интента или утверждённую структуру.

## Порядок

1. SEO-preflight подтверждает самостоятельный интент, владельца URL, целевой документ и обязательные ссылки.
2. Текст готовится только после значения `РАЗРЕШЕНО`.
3. Автор сохраняет утверждённые H1, H2, их порядок и карту `запрос → раздел`.
4. Коммерческая логика встраивается в существующие разделы, а не добавляется одинаковыми H2 во все статьи.
5. После черновика запускается редакционный контроль.
6. Затем проходят юридическая проверка, полный `npm run check`, CI, deployment и live-аудит.

## Что должно быть в статье

- признаки, по которым читатель узнаёт свой сценарий;
- одна ключевая правовая развилка;
- конкретная цена ошибки: действие → возражение или потеря → последствие;
- объяснение, почему универсальный шаблон не закрывает конкретную ситуацию;
- граница между безопасными самостоятельными действиями и работой юриста;
- состав одной платной юридической работы и её проверяемый результат;
- реальное возражение клиента и спокойный ответ без давления;
- тематический CTA, ведущий к одному заранее утверждённому документу;
- честная граница результата без обещаний победы или взыскания.

## Редакционный контроль после черновика

Проверка блокирует публикацию, если:

- изменены утверждённые разделы или их порядок;
- одна и та же мысль повторяется в разных абзацах;
- появился отдельный рекламный раздел, не предусмотренный структурой;
- цена ошибки описана общими словами без последствия;
- CTA не связан с целевым документом;
- не объяснено, что человек может сделать сам и что именно делает юрист;
- используются канцелярские формулы вместо простого языка;
- объём вырос без новой правовой развилки, доказательства или действия;
- внутренняя SEO-кухня, ID источников или неподтверждённые результаты попали в публичный текст.

## Автоматический контракт

Статья включает `editorialGateVersion: 1`, когда для неё подготовлены все данные шлюза. Команда `npm run test:editorial-commercial-gate` проверяет обязательные поля CTA, цену ошибки, границу самостоятельных действий, состав работы юриста, честную границу результата, повторные абзацы и запрещённые канцелярские формулы.

Специальный тест статьи отдельно фиксирует утверждённый порядок H2 и юридические границы конкретного сценария.
