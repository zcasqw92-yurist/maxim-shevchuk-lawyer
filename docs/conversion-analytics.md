# Аналитика CTA, источников и обращений

Дата: 30.07.2026.

## Цель

Система должна показывать не только общий клик по WhatsApp или Telegram, но и полный обезличенный путь до него:

1. откуда пользователь впервые перешёл на сайт;
2. на какую страницу попал;
3. какие внутренние страницы посетил в текущей вкладке;
4. какую кнопку увидел и нажал;
5. на какой странице и в каком блоке она находилась;
6. какую общую юридическую тему выбрал;
7. открыл ли окно выбора мессенджера;
8. какой канал выбрал в итоге.

Текст подготовленного сообщения, документы, имя, телефон посетителя, содержание переписки и значения рекламных click ID в аналитику не передаются.

## Источник перехода

Яндекс Метрика самостоятельно определяет источник по рефереру и меткам первого просмотра визита. Сайт не подменяет эту атрибуцию, а дополняет её first-touch параметрами и внутренним путём посетителя.

До согласия аналитические скрипты не запускаются и данные не отправляются внешним системам. В `sessionStorage` текущей вкладки временно сохраняются только:

- путь первой посадочной страницы;
- тип первой страницы;
- домен и путь внешнего реферера без query-параметров;
- разрешённые UTM-метки;
- названия обнаруженных click ID без их значений;
- последовательность внутренних pathname.

При отказе эти значения удаляются. После закрытия вкладки `sessionStorage` очищается браузером.

После согласия first-touch параметры передаются в Яндекс Метрику методом `params` в объекте `traffic_attribution` и дублируются в параметрах CTA-событий.

## События

### `traffic_attribution_ready`

First-touch контекст подготовлен к передаче в аналитическую систему. В Яндекс Метрику он передаётся как параметр визита, а в `dataLayer` — как техническое событие.

### `cta_view`

CTA оказался видим пользователю не менее чем на 60%. Событие используется как знаменатель для расчёта кликабельности конкретного блока.

### `cta_click`

Пользователь нажал CTA. Сюда входят кнопки открытия диалога, быстрые ситуации, мобильная панель и прямые способы связи.

### `messenger_dialog_open`

Сохраняемая микроконверсия существующего сайта: открылось окно выбора WhatsApp или Telegram.

### `contact_conversion`

Главная конверсия: пользователь выбрал телефон, email, Telegram или WhatsApp. Для перехода через диалог передаются как сведения о кнопке мессенджера, так и исходный CTA, с которого пользователь начал путь.

### `contact_action`

Дополнительное действие, которое не считается прямым обращением, например открытие карты.

## Параметры CTA

Каждое CTA-событие содержит:

- `page_path` — URL страницы;
- `page_group` — тип страницы: главная, услуга, статья, практика, контакты и т. д.;
- `viewport` — desktop, tablet или mobile;
- `content_kind` — тип текущего материала;
- `content_id` — ID или slug материала;
- `cta_id` — стабильный идентификатор CTA;
- `cta_label` — видимый текст кнопки;
- `cta_placement` — блок размещения;
- `cta_variant` — основной, вторичный, текстовый, карточка контакта и т. д.;
- `cta_kind` — открытие диалога либо прямой контакт;
- `section_title` — заголовок ближайшего смыслового блока;
- `topic` — выбранная юридическая тема;
- `channel` — phone, email, telegram, whatsapp или map;
- `contact_mode` — direct либо dialog.

Для итоговой конверсии дополнительно передаются универсальные поля источника CTA:

- `source_cta_id`;
- `source_cta_label`;
- `source_cta_placement`;
- `source_cta_variant`.

Если пользователь выбрал мессенджер через диалог, также сохраняются `origin_cta_*` исходной кнопки.

## Параметры трафика

Каждое CTA-событие содержит:

- `traffic_source_type` — `tagged`, `referral` или `direct`;
- `traffic_landing_path` — первая страница текущей вкладки;
- `traffic_landing_group` — тип первой страницы;
- `traffic_initial_referrer_host` — внешний домен без query;
- `traffic_initial_referrer_path` — внешний pathname без query;
- `traffic_utm_source`;
- `traffic_utm_medium`;
- `traffic_utm_campaign`;
- `traffic_utm_content`;
- `traffic_utm_term`;
- `traffic_utm_referrer`;
- `traffic_click_ids` — только перечень присутствующих типов `yclid`, `gclid`, `fbclid`, без значений;
- `traffic_journey_depth` — число посещённых внутренних страниц;
- `traffic_journey_first_path`;
- `traffic_journey_previous_path`;
- `traffic_journey_tail` — до четырёх последних внутренних pathname.

## Стандарт внешних ссылок

Единые названия площадок, каналов, кампаний и готовые хвосты закреплены в:

```text
docs/traffic-attribution-standard.md
```

Любая самостоятельно размещаемая ссылка должна соответствовать этому документу.

## Настройка целей в Яндекс Метрике

Счётчик: `111050150`.

В интерфейсе Метрики нужно создать цели типа **JavaScript-событие** с точными идентификаторами:

1. `contact_conversion` — основная цель обращения;
2. `messenger_dialog_open` — открытие выбора мессенджера;
3. `cta_click` — диагностическая микроконверсия;
4. `cta_view` — диагностический показ CTA.

`contact_action` можно создать отдельной целью только для анализа карты и иных вспомогательных действий. В число основных обращений её включать не следует.

Для `traffic_attribution_ready` отдельная цель не нужна: источник передаётся как параметр визита методом `params`.

## Основные отчёты

После накопления данных сравниваются:

- `contact_conversion` по `traffic_utm_source`, `traffic_utm_campaign` и `traffic_utm_content`;
- `contact_conversion` по `traffic_landing_path`;
- `contact_conversion` по `source_cta_placement`;
- `contact_conversion` по `source_cta_label`;
- `contact_conversion` по `page_group` и `page_path`;
- каналы по параметру `channel`;
- темы по параметру `topic`;
- путь по `traffic_journey_tail` и `traffic_journey_depth`;
- кликабельность CTA: `cta_click / cta_view`;
- переход от открытия диалога к выбору канала: `contact_conversion / messenger_dialog_open`.

## Контроль

`npm run test:conversion-analytics` проверяет:

- подключение модуля на всех публичных страницах;
- first-touch атрибуцию по UTM и внешнему рефереру;
- передачу параметров визита методом `params`;
- сохранение источника при внутреннем переходе;
- события показа, клика и итогового обращения;
- передачу страницы, материала, блока, формулировки, темы и канала;
- сохранение исходного CTA после выбора мессенджера;
- отсутствие текста черновика сообщения;
- отсутствие значений `yclid`, `gclid`, `fbclid` и query-параметров внешнего реферера.
